# Прораб-память — Telegram-бот

Читает рабочие чаты объектов, извлекает договорённости / задачи / проблемы / вопросы
со ссылкой на исходное сообщение и уровнем достоверности (🟢 подтверждено, 🟡 со слов, 🔴 конфликт).

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # вписать BOT_TOKEN и OPENROUTER_API_KEY
.venv/bin/python -m bot
```

## Подготовка в Telegram

1. BotFather → `/setprivacy` → Disable (или дать боту права админа в группе) — иначе бот не видит сообщения.
2. Руководитель пишет боту `/start` в личку (первый написавший станет руководителем, если `MANAGER_IDS` пуст).
3. Добавить бота в чат объекта, сделать админом, написать `/setup Ленина 5`.
4. Сотрудники нажимают `/start` у бота — чтобы он мог писать им лично.

Ссылки `t.me/c/...` на сообщения работают только в супергруппах. В обычной группе вместо ссылки бот показывает
команду `/src_<id>` и кнопки «📎 #id»: по ним он присылает исходное сообщение (в том же чате — ответом на него,
в личке — пересылкой). При превращении группы в супергруппу бот сам обновит её id.

## Чат компании с топиками

- Один чат компании (супергруппа с топиками), каждый объект — свой топик: внутри топика `/setup Название`.
- В топике «Статусы объектов» — `/statuses`: туда бот публикует смены этапов по всем объектам.
- Контекст, вопросы бота и ответы не смешиваются между топиками. Старые отдельные чаты объектов тоже работают.
- Сотрудник пишет боту `/start` в личку и указывает ФИО (сменить — `/fio`). После этого задачу ему можно
  поставить по имени-отчеству в любом падеже: «@бот задачу Ивану Петровичу заказать бетон». Если подходят
  двое — бот не назначает наугад, а пишет, что не нашёл.

## Как работает

- **Поток (без тега).** Бот молча читает все сообщения, включая голосовые и фото, и сам замечает задачи,
  договорённости и проблемы (👁 «замечено ботом»). В чат он пишет только реакции и короткие уточнения.
- **По тегу `@бот`** включаются режимы, записи получают пометку ✍️ «зафиксировано человеком»:
  - `зафиксируй… / в доп / запиши…` — карточка 🚨 инцидента или ✅ договорённости;
  - `задачу @иван… / дедлайн…` — карточка ⚡️ задачи, личка исполнителю, кнопка «Подтвердить выполнение»;
  - `что по… / как там… / статус…` — карточка ℹ️ статуса: последнее изменение, затык, ближайшая веха;
  - непонятно — черновик и кнопки «Зафиксировать как: Проблема / Задача / Договорённость / Вопрос руководителю»;
  - остальное (привет, вопрос про документ, постороннее) — обычный ответ.
- **Голосовые** расшифровываются, **фото** описываются, с них читается текст, скрины переписки разбираются отдельно
  (`MEDIA_MODEL`). Скрин переписки с клиентом даёт 🟢, если собеседник не сотрудник, а дата на скрине не позже отправки.
  Для аудио OpenRouter требует на балансе аккаунта не меньше $0.50. Голосовые переводятся в mp3 через ffmpeg.

## Структура

| Файл | Что делает |
|---|---|
| `bot/__main__.py` | запуск, команды, планировщик сводки |
| `bot/handlers.py` | хендлеры: личка, группа, правки, кнопки |
| `bot/pipeline.py` | конвейер: нормализация → правила/LLM → записи → реакции и сигналы |
| `bot/modes.py` | режимы по тегу и карточки-шаблоны |
| `bot/media.py` | голосовые и фото → текст |
| `bot/clarify.py` | уточняющие вопросы бота |
| `bot/files.py` | чтение документов |
| `bot/llm.py` | LLM через OpenRouter (модель в `LLM_MODEL`): извлечение и ответы |
| `bot/db.py` | SQLite: объекты, копии сообщений, правки, записи |
| `bot/digest.py` | утренняя сводка и `/brief` |
| `bot/formatting.py` | ссылки на сообщения, форматирование |

## Сервер

Бот работает на `89.37.192.178` (Ubuntu 24.04) службой systemd `olimp-bot`, код в `/opt/olimp/app`,
база `/opt/olimp/app/bot.db`. Mini App: https://olimp.cdnvidikturbik.online/ (HTTPS — Caddy, `/etc/caddy/Caddyfile`).
В личке бота кнопка «Объекты» слева от поля ввода и команда `/app`.

```bash
ssh root@89.37.192.178 'journalctl -u olimp-bot -f'          # логи
ssh root@89.37.192.178 'systemctl restart olimp-bot'          # перезапуск
rsync -az --exclude .venv --exclude bot.db --exclude .env --exclude __pycache__ ./ root@89.37.192.178:/opt/olimp/app/ \
  && ssh root@89.37.192.178 'chown -R olimp:olimp /opt/olimp && systemctl restart olimp-bot'   # выкатить код
```

Локально бота не запускать, пока работает серверный: Telegram отдаёт сообщения только одной копии.
